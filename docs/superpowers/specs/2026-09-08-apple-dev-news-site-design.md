## 1. 背景与定位

面向中国 Apple 开发者的资讯 + 教程网站。核心差异化：

1. **政策与生态情报**：系统跟踪 Apple 官方动态（佣金政策、审核规则、SDK 强制要求、发布会/WWDC），中文圈目前几乎无人系统覆盖。
2. **时效性**：AI 辅助管线实现日更；人工教程保证深度。

竞争参照：SwiftGG（翻译为主）、老司机技术、壹博客、WWDC 内参。它们的共同弱点是政策/生态情报覆盖薄、时效差，本站以「情报 + 教程」双轮切入。

## 2. 目标与受众

- **受众**：中国 Apple 开发者（iOS/macOS/visionOS 开发者、独立开发者、团队技术负责人）。
- **变现**：先流量后变现（6 个月后再评估：开发者工具广告、课程赞助、付费专栏）。
- **成功标准（前 90 天）**：
  - 资讯管线日更稳定运行（≥80% 工作日有产出）
  - 教程 8–12 篇（含「适配 iOS 27」系列）
  - Google Search Console 收录 ≥100 页，自然搜索月点击 >1,000
  - 微信公众号开通并同步更新

## 3. 技术方案（已选定方案 A）

- **站点**：Astro SSG + Markdown 内容集合（Content Collections）。
- **主题/样式**：自定义轻量主题，遵循内容站可读性优先；深色模式。
- **评论**：初期 giscus（GitHub Discussions），不引入账号系统。
- **分析**：先接 Google Search Console + 一个轻量隐私友好统计（如 Cloudflare Web Analytics 或 Umami 自托管）。
- **部署**：Cloudflare Pages（首选，国内可达性相对好）或 Vercel；构建即部署（git push 触发）。
- **明确不做（YAGNI）**：用户系统、付费墙、自建评论、服务端渲染、数据库。初期全部后置。

## 5. 内容管线（复用 electric-economy 思路）

```
Apple 官方 RSS/页面 → 抓取（定时）
  → LLM 翻译 + 摘要 + 结构化 frontmatter（标题/标签/原文链接）
  → 生成 Markdown 草稿（草稿目录，frontmatter 标记 draft: true）
  → 人工审核（事实核对：数字、日期、佣金率等必须比对原文）
  → 移入正式内容目录 → git commit → CI 自动构建部署
```

- 信源（初版）：developer.apple.com/news RSS、Apple Developer 更新页、WWDC session 标题列表、Apple Newsroom。逐步加入第三方（如 9to5Mac/MacStories）但保持「官方为主」的定位。
- 管线实现独立于 electric-economy 代码库（借鉴架构：抓取 → 队列 → LLM → 产出），避免耦合其业务模型（商机评分）。
- LLM 幻觉防线：所有关键数字/日期必须人工与原文核对后才能去除 draft 标记；资讯页固定展示「来源 + 原文链接」。

## 6. SEO 与分发策略

- **关键词策略**：抢占事件型长尾（「iOS 27 适配」「Xcode 27 新功能」「App Store 佣金 25%」等），教程做常青词（「SwiftUI 教程」「Swift 7 concurrency」）。
- **站点规范**：语义化 HTML、每页独立 title/description、sitemap.xml、结构化数据（Article）、中文内容 lang=zh-CN。
- **多渠道分发（1 主站 + 4 分发）**：主站沉淀资产；微信公众号（必做）、掘金专栏、知乎、B 站（可选，视频化后置）。分发为「摘录 + 链接回主站」模式。
- **部署地域**：境外托管免备案起步；若后期百度流量变得关键，再评估国内备案 + CDN，不在本期范围。

## 8. 风险与对策

| 风险 | 对策 |
